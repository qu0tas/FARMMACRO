# K2-014 — производительность и диагностика / alpha20

Minecraft26.1.2, FabricLoader0.19.5, FabricAPI0.155.3+26.1.2, Java25. Это alpha, не стабильный2.0.0. Реализация и статическая ревизия завершены; игровая/визуальная приёмка и измерения пользователем НЕ пройдены.

## Что изменено

### Поиск Combat / Pests
- Один ленивый discovery-снимок загруженных сущностей на клиентский тик, до8192. Его делят MobNames и discovery-проходы PestHunter/Lasso/Traps; не все обходы игры/мода заменены. При лимите снимок неполон, ENTITY_LIMIT виден в отчёте. Новый мир/следующий тик сбрасывают снимок. Никаких новых/невидимых серверных сущностей он не создаёт.
- MobNames нормализует текст armorstand-метки один раз на проход, а не при каждом сравнении с соседним телом. Метка остаётся только именем; целью остаётся реальное тело.
- Первичный захват не откладывается интервалом ESP. Idle-подсветка coarse-видимости раз в4тика, активная обычная — раз в2тика; при необходимости захвата/Special — немедленно. Если ни захват, ни подсветка не нужны, discovery не выполняется.
- До128 обычных coarse body-проб за тик, плюс текущий живой захват и подтверждённый Special. Одна проба — до9 лучей как раньше. Ближайшие32 в приоритете; хвост циклически сдвигается, чтобы закрытые ближние не навечно вытесняли дальние. В густой сцене обнаружение может занять несколько тиков. Не обещаем прежнюю полноту/задержку при переполнении8192.
- BUDGET явно отличается от COVER (стена), RANGE, FILTER, FOV, WAITING, SPECIAL, INVALID. Причины выбора видны в прежней Combat-диагностике. Это не повод стрелять через стену или по старой геометрии.
- Проверки фактического выстрела, frame-наведения, живого захвата, End/ручного ввода/паники, мира и collision-коридоров не заменены долгоживущим кешем и не замедлены. Никаких новых обходов staff/античита или автореакций.

### HUD и ESP
- Все19 ID плашек, F8-позиции/масштаб/скрытие,14вкладок и28биндов сохранены.
- В новых6карточках одна подготовка на измерение+рисование; TaskSnapshot читается один раз на layout. Экономика/Farming/Pet готовят текст до10раз/с; общая задача/Combat/Pests — каждый layout. Паника не ждёт100мс кеша числовых карточек. Внутри layout текст/высота согласованы; при отсутствии мира кеш карточек очищается.
- Массивы графика копируются при подготовке экономики, а не каждый render; подпись/масштаб графика также подготовлены заранее. Позиции и реальные числа не выдумываются.
- У 12 рёбер ESP убраны вложенные временные массивы координат/граней. Сохраняются depth-tested геометрия, живые проверки сущности и прежние цвета/форма. Это не переход на xray, glow или NanoVG.
- Не заявляется универсальное размещение на любом GUI scale: прежний F8/Compact/предупреждение переполнения остаются. Визуальная приёмка нужна.

### Фоновые работы и память
- Поиск пути: один daemon worker + ArrayBlockingQueue(1), отказ при переполнении как обычное отсутствие результата, не бесконечная очередь. Отмена ожидающей задачи удаляет её Runnable/снимок из очереди; текущий поиск отменяется кооперативно. Автоматического resume не добавлено.
- Снимок до4096 непустых копируемых секций: превышение отклоняет ВСЮ задачу с причиной; отсутствующие клетки не превращаются в воздух. Это предел работы/памяти, не гарантия длительности копирования в главном потоке.
- Для worker установлен кооперативный5с бюджет с проверками отмены в A* и между чтениями/декодами cache. Существующие maxNodes и тайм-аут контроллера сохранены. Дисковый IO/копирование/отдельная итерация не принудительно прерываются ровно на5.000с.
- Загрузка cache <=128 чанков /32MiB удерживаемых массивов coarse-ячеек. Это не общий предел Java heap: есть структуры, сжатые region-буферы и кратковременные копии декодирования. Недозагруженный cache остаётся неизвестным и может дать честный отказ/перестроение, не слепую ходьбу.
- Старый ChunkCache IO остаётся1worker/queue32/coalescing. Новая capture при уже полной очереди без pending-ID отбрасывается ДО копирования; rejected cleanup убирает и pending, и latest. Небольшие уже pending-обновления коалесцируются как раньше.
- HttpClient публичных Bazaar-цен закрывается try-with-resources при успехе/ошибке/отклонённом epoch. Прежние OFF-согласие,60с,8MB,15с-request/8с-connect,TTL/429 и отсутствие player/key payload не изменены; runtime feed агентом не вызывался.
- Guard: первый stacktrace в локальном логе, повторы максимум раз в30с/внутренний ключ, счётчик не теряется. Отключение сломавшегося HUD/шага сохраняется. В общий отчёт stacktrace/сообщение исключения не включаются.

## Настройки
Visual → **K2 · Производительность и диагностика**, прежние PERF/F9, LowRender/F7 и Ungrab/U остаются; новых клавиш/вкладок нет.

Дополнения действуют только при активном PERF:
- «Фоновый FPS»:0=нет доп. ограничения, положительный cap только уменьшает vanilla limit в неактивном окне. Не повышает FPS свёрнутого/AFK-окна. При pending handoff дополнительный cap не применяется (ванильный лимит и обычный PERF FPS остаются).
- «Лимит чанков»:0=не менять,2–32=временно снизить renderDistance до min(прошлый,cap). Это не изменение server distance, кэша, навигационной истины и не второй LowRender. При ручном изменении опция перестаёт принадлежать режиму до его нового включения (или0→cap).
- «Убрать осколки ломания»:OFF. Только ClientLevel.addDestroyBlockEffect/addBreakingBlockEffect. Не отменяем серверные частицы, Tracker, события/пакеты ломания, взаимодействие с блоком.
- «Громкость окружения»:100%. Масштаб BLOCKS/HOSTILE/NEUTRAL/AMBIENT/WEATHER на новых/пересчитанных звуках. MASTER/паника, PLAYERS, UI и музыка не масштабируются. Уже играющие каналы могут сохранить прежнюю громкость до нового/пересчитанного звука. Это не обещание немедленного полного mute и не снижение CPU всех звуков.

Все новые ограничения по умолчанию0/OFF, звук100%. Режим сохраняет прежние графические настройки перед применением; восстанавливает только значения, всё ещё совпадающие с установленными режимом. Ручной пользовательский выбор не перезаписывается. Значение, вручную возвращённое точно к установленному режимом, неотличимо от собственного. Смена полного профиля сначала завершает старый PERF; выход из мира завершает и ручной режим; служебные restore/applied-поля не импортируются из профиля. В случае ошибки восстановления остальные опции возвращаются независимо; сохранённый остаток остаётся для следующей попытки. Auto-PERF (старый opt-in) теперь охватывает фермы/Combat/Pests/сервисы.

Фокус НЕ подделывается и не захватывается новой оптимизацией; U/Ungrab/PiP остаются существующими механизмами. Стоп Combat/навигации при потере фокуса не обходится. Паника/алярм/ручная передача приоритетны.

## Приёмка пользователем
1. Те же28биндов/14вкладок/F8 позиции; Compact/full/merged и три темы, разные GUI scale, нет прыжков высоты. Паника видна сразу.
2. Combat: обычная/дальняя/много целей/стена/фильтр/FOV; BUDGET отдельно, дальние постепенно попадают в проход. Текущий захват и Special проверяются без ожидания tail/ESP. Без наведения/ESP лишнего discovery нет.
3. Pests/Vacuum/Lasso/Traps и мир/респавн: нет старой сущности в новом мире; ожидание chunk/дверь/перестроение/отказ читаемы. End/ручной ввод/паника освобождают управление; нет автопродолжения.
4. Короткий/длинный путь/очередь/отмена: отказ при лимитах понятен; cache mismatch остаётся unknown. Не увеличивай лимиты до проверки своей памяти/сервера.
5. PERF manual/auto/Combat/services; фон/сворачивание/паника; чанки0/cap; LowRender+PERF; локальные осколки OFF/ON при сохранённом Tracker; ручное изменение FPS/чанков/облаков/теней/дальности сущностей затем выключение; profile change/выход/перезапуск.
6. Volume0/50/100: окружение vs MASTER/паника/UI/игрок; уже играющий звук может смениться не сразу. Новые дополнительные настройки OFF по умолчанию.
7. Скопировать отчёт: проверить отсутствие личного текста и наличие причины отказа/переходов. Частные локальные файлы не включать.
8. Сравнить FPS/стабильность на своих одинаковых сценах до/после самому. Агент Minecraft/тесты/симуляции/бенчмарки/GUI-стенд НЕ запускал.
