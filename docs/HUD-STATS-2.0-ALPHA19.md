# K2-013 — экономика, Farming XP и HUD · alpha19

Реализация для доступных ниже источников завершена; игровая/визуальная приёмка НЕ пройдена. Это не stable2.0.0. Следующий этап K2-014. Ни Minecraft, ни тесты, ни визуальный стенд агент не запускал.

## Где настройки

**Визуал → K2 HUD / General**, затем «Экономика: источники и пределы» и «Farming XP / питомец». Существующие 14 вкладок и 28 биндов сохранены. F8 — прежний редактор: ЛКМ переместить, колесо масштаб, ПКМ скрыть. Настройки управления/паники не продублированы в HUD.

По умолчанию пассивная статистика и новые плашки включены, **Compact включён**; публичные рыночные запросы и сохранение daily/lifetime **выключены**. Никакой новый флаг не разрешает покупки, ввод, открытие меню или запуск макроса.

## Что означает «экономика»

| Метрика | Что действительно известно | Чего она не обещает |
|---|---|---|
| Учтённые поступления | Свои продажи контроллером StashSales после квитанции Bazaar **и** существующего серверного подтверждения инвентаря | Не любая продажа, не цена добычи и не доход только новых вещей |
| Учтённые расходы | Свои покупки контроллером визиторов после квитанции **и** добавления предметов | Не все расходы, не итоговое потребление вещей, не Tip Jar |
| Учтённый поток | Эти поступления минус эти расходы | **Не чистая прибыль фарма**; старые запасы тоже могут быть проданы |
| Поток / час | Накопленный учтённый поток / наблюдаемое время SkyBlock | Не активный темп только фермы, не гарантированный будущий заработок |
| Инвентарь ≈ | Оценка обычных стаков из 36 слотов по выбранному источнику + покрытие известных/неизвестных стаков | Не весь аккаунт, не sacks/стеш/Hunting Box; не заработок; не оценка улучшенной экипировки |
| Hunting shards ≈ | Только реальные ATTRIBUTE_SHARD уровня1 с одним известным атрибутом в этих слотах, точное соответствие Bazaar-ID | Не виртуальная Hunting Box, не число поимок, не каждый будущий атрибут |

Оценка инвентаря **не складывается** с поступлениями: это могло бы посчитать одну вещь дважды. Обычные стаки с UUID/неизвестными ExtraAttributes/зачарованиями пропускаются. У шардов допускается только известное поле единственного атрибута уровня1; неизвестный/неторгуемый вариант не получает выдуманную цену.

Нет подходящих квитанций/цен/XP → `—`, а не точный ноль дохода. Ноль наблюдавшихся подтверждённых событий и пустая наблюдавшаяся минута допустимы как **учтённый** ноль, не как утверждение «в игре ничего не заработано». Известная часть оценки инвентаря сопровождается покрытием, не выдаётся за полную стоимость. Продажи округляются вниз, покупки вверх существующими контроллерами до целых coins; мелкая разница округления возможна.

## Сессия статистики и график

Это **сессия наблюдения**, не бюджет Scheduler из K2-012. Начинается при первом распознанном SkyBlock в клиенте/смене сервера или аккаунта/ручном сбросе. Перерыв, сервис и обычная смена SkyBlock-мира сами счётчики поступлений не обнуляют. Между отключениями временной знаменатель не идёт. Переключение SkyBlock-профиля на том же аккаунте автоматически не распознаётся: сбрось статистическую сессию вручную. В каждом наблюдавшемся тике засчитывается максимум 1с, длинное зависание не выдаётся за точно наблюдавшееся время.

Rolling-график — 30 минут **учтённого потока coins/мин**, положительные/отрицательные столбики с общей нулевой осью. Серые отметки — минута без наблюдения, не нулевой заработок. Текущая минута частичная (`сейчас*`), крайние точки окна не обещают ровно 30 полных минут. Только полный режим; Compact оставляет числа. График не «достраивается» примерными данными и не сохраняет историю после перезапуска.

## Источник цен

- **NPC**: встроенный snapshot официальных `resources/skyblock/items`, только base npc_sell_price; дата обновления источника в JSON ресурсе. Это не динамическая оценка экипировки и не автоматически актуальная навсегда цена. Для Hunting-шардов NPC-цена не выдумывается.
- **Bazaar**: отдельно разрешённый публичный GET фиксированного `api.hypixel.net/v2/skyblock/bazaar`, без API key/ника/UUID/профиля. Не чаще 60с, один запрос одновременно, конечные таймауты, тело ≤8MB, без редиректов. Учитывается Retry-After при429; не делается мгновенный повтор того же запроса.
- Для оценки используется лучший bid из `sell_summary` (цена, которую может получить продавец), **до налога**, без гарантии доступной глубины/количества/проскальзывания. Это котировка, не приказ/клик/финансовое разрешение. Snapshot сервера старше5мин и локальная котировка старше5мин не принимаются.
- Выключение отзывает ожидание результата, уже начатый GET может завершиться без применения результата. Источник/разрешение/TTL изменились → старая оценка перестаёт показываться. Ошибки статуса содержат только тип, без сетевого тела/аккаунтных данных.

Полные ссылки и лицензии: `docs/K013-DATA-SOURCES.md`. В JAR вложен полный MIT notice справочника соответствий шардов (Copyright2020 Moulberry). Код/ассеты Aether и SkyHanni не копировались/адаптировались.

## Daily / lifetime и сброс

Отдельный флаг OFF, файл `config/farmmacro/statistics.json`. **Все профили/аккаунты устройства вместе**, не полный аккаунтный API-доход. Сохраняются только сумма поступлений/расходов, наблюдённый XP, число квитанций, текущая локальная календарная дата и дневные суммы. Нет сервера/ника/UUID/координат/чата/токенов. День = системная локальная дата JVM; смена даты/часового пояса начинает новый дневной bucket, не меняя lifetime. Архива произвольных прошлых дней пока нет.

Ограниченный файл/схема/диапазоны. Один фоновый IO-поток, объединение ожидающих записей, временный файл + атомарная замена где поддержана, поколение сброса/выключения не даёт старой ожидающей записи восстановить прошлые суммы. Checkpoint примерно каждые10с и после подтверждённых денег; crash может потерять последний интервал XP. При выключении прежний файл остаётся. Из локальных итогов **никогда** не восстанавливается управление/сессия макроса/reconnect.

Сбросы отдельно: статистическая сессия или всё вместе с daily/lifetime. Требуется второй клик за3с. Полный сброс доступен при включённом сохранении. Не сбрасывает игровые coins/XP/макросы/позиции HUD. При импорте конфигов локальные разрешения Bazaar/сохранения не заимствуются из переносимого профиля.

## Farming XP

- Уровни0–60 и суммарные пороги — официальный resource skills. Полная шкала60:111672425XP.
- Только серверный overlay/actionbar с однозначным `Farming(current/max)`. Приходящий в чат текст не является XP-источником. Постоянно повторяющееся `+6 Farming` **не суммируется**.
- Изменение абсолютного прогресса в том же мире за≤15с даёт наблюдаемый прирост; повтор/недавнее уменьшение не дублирует XP. Первый образец только задаёт базу. Смена мира, большой разрыв, неизвестный/двусмысленный формат не заполняются предположениями.
- Прогресс может быть округлён сервером. Наблюдаемый прирост — неполная оценка: другие HUD-моды, пропущенные actionbar, крупный скачок >100000XP или другой язык могут оставить `—`/недоучёт. Он не обещает полный API-total.
- Темп после≥60с наблюдения; ETA next и теоретическая ETA60 по этому темпу, не гарантия. Достигнутая известная цель имеет ETA «достигнуто». Текущий абсолютный прогресс старше60с не выдаётся за свежий.
- Farming cap пользователь задаёт сам (default50). Мод не утверждает, что куплены уровни Anita, и ничего не разблокирует. У cap поле объясняет условность60.

## Питомец

Сведения из Tab «Pet» либо видимого серверного Pets-меню с единственным активным предметом. Сам HUD не открывает Pets/не вызывает питомца. Имя/уровень/редкость показываются только когда разобраны, возраст≤60с. Незнакомая раскраска → редкость `?`; не догадка по имени.

Max level показывается только при явной серверной надписи MAX LEVEL у активного предмета; иначе `?`. Аукционная стоимость неизвестна: Bazaar не является рынком питомцев. Можно сделать **ручную ценовую пометку** для наблюдавшихся типа/редкости; она не называется свежей рыночной ценой и не добавляется к заработку/инвентарю. Уникальные улучшения питомца этой пометкой не оцениваются.

## HUD / совместимость

Новые карточки: General/активная задача, экономика, Farms/XP, питомец, Combat, Pests. Старые status/editor/hold/mouselock/view/human/return/delays/susp/panic/server/schedule/nav и `all` остаются с теми же ID. Их места/якоря/масштаб/видимость/личные цвета автоматически не переписываются. Разделы Combat/Farms/Pests/Navigation/General включаются отдельно.

Новые непоставленные карточки автоматически слева, прежняя стопка справа. Compact — меньше строк, полный — детали/источники/график. Slate/DeepBlue/Paper — отдельные HUD-палитры, согласованные интервалы/бордеры/текст. Меню продолжает использовать свою тему. Пользовательский фон/прозрачность/картинка/цвет может снизить контраст; проверь у себя.

F8 использует существующий редактор (перенос, масштаб, скрыть, объединить, сброс по явной кнопке). Предупреждает о выходе фактических плашек за доступный экран/область кнопок. Полный режим/общая панель/очень большой масштаб на маленьком GUI может не поместиться: уменьши масштаб, Compact или скрой/переставь лишнее. Агент **не проверял** пиксельную читаемость на твоём разрешении и не обещает универсальный автоматический fit.

TaskSnapshot читает фактического владельца/состояние: работа, ожидание, подготовка/подтверждение, пауза, ручное управление. Продажи отдельно показывают ожидание квитанции; другие сервисы используют собственный статус. Профиль/источник, цель/элемент, Shift, причина паники и подсказка нового запуска не являются новыми командами. Pending-паника имеет приоритет в General и существующем аварийном оверлее. Ни один draw/getter не вызывает resume/перехват/действия игры.

## Приёмка пользователем (агентом не выполнена)

1. Резервная копия config, один JAR в mods. Сравни прежние места F8; новые карточки слева, Compact default.
2. На своём GUI scale проверь Slate/Blue/Paper, ширину120/190/480, отдельные/объединённые карточки, скрытие групп/плашек, перетаскивание/привязки/колесо, смену размеров окна. Пользовательский фон проверяй отдельно.
3. В Farm/Combat/Pests/навигации/сервисе/перерыве/панике смотри актуальные статус/профиль/Shift/причину/handoff. Открытие редактора не должно незаметно продолжать модуль.
4. Без квитанций поток `—`. На отдельно разрешённой малой сделке сопоставь фактическую квитанцию+инвентарь с учтённой суммой (с округлением). Ручные/неподтверждённые сделки не должны выдавать доход контроллера. Не выполняй финансовые операции только ради теста без своего решения.
5. Движение вещей/оценка инвентаря не должны увеличивать поток. Для шардов NPC остаётся неизвестным; если разрешишь Bazaar, проверь известный level1 ATTRIBUTE_SHARD и неизвестный/многоатрибутный/виртуальную Hunting Box.
6. XP: повтор actionbar без прогресса, прирост, level-up, разрыв/другой мир, скрытый HUD, cap50/60. Проверить, что ETA не выдумывается без темпа.
7. Питомец в Tab/вручную открытом Pets/другой питомец/истечение TTL. Неизвестные rarity/max/price не превращаются в выдуманные100/0coins.
8. При желании включить локальные итоги, проверить перезапуск/локальную дату/два сброса/импорт профиля. Управление из statistics.json не запускается. Не публиковать папку config.
