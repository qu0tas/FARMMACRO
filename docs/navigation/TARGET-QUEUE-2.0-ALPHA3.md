# 2.0.0-alpha.3 — локальная очередь, Special и диагностика

## Объём

K2-002 пакет2b, плюс небольшой исправленный путь ручной отмены Special из K2-003. Не весь2.0 и не утверждение об игровой приёмке. Модель камеры/частичного укрытия alpha.1–2 сохранена.

## Очередь соседей

Сохраняется порядок: локальная группа перед камерой → более широкий близкий сектор → другие перед камерой → задний fallback. Уже захваченный живой доступный моб не переключается только из-за появления более удобного.

Новые детали:
- После выстрела якорь цепочки связан с прошлой реальной сущностью. Пока она жива/доступна в том же мире, берётся её актуальное положение; иначе остаётся последний известный центр. Якорь ограничен6сек и очищается при ручном/контекстном сбросе. Исчезновение всё ещё не означает убийство.
- Когда локальные открытые соседи (band0/1) ожидают результат выстрела, а лучшая свободная замена только дальняя или задняя (band3/4), переключение кратко откладывается.
- `aimChainRearWaitMs`: default350,0–1500мс, настройка выбранного Combat-профиля.0 выключает ожидание. Отсчёт начинается от отправленного выстрела и НЕ продлевается повторными поисками.
- Свободные кандидаты band0/1/2 выбираются без этой задержки. Special не участвует в обычном ожидании. Полностью закрытые, отфильтрованные или внеFOV соседи не удерживают эту очередь.
- Это не время полёта болта и не гарантия, что350мс достаточно. Старое окно наблюдения цели (`aimShotObservationMs`, default900) существует отдельно.
- Во время ожидания цели нет: нет выстрела/поворота idle вместо неё. Независимый явно включённый A/D-режим этим не выключается.
- При равной категории/оценке/дистанции используется стабильный entity ID, не порядок обхода списка мира. Оценка и дистанция сравниваются по фиксированным корзинам1e-6, а не нетранзитивным попарным epsilon.

## Свежесть поиска и Special

При реальном новом захвате список обновляется сразу, а не только по очередному двухтиковому ESP-таймеру. Если старый захват признан недействительным уже после начального решения scan в том же тике, перед новым выбором тоже гарантируется свежий список; повторного scan, уже выполненного в этот тик, нет. Невозможность активироваться (контекст/оружие/пауза) сама по себе не повышает частоту сканирования. Основная частота при удержании обычной цели остаётся прежней.

Подтверждённый Special focus добавляется в свежий список, если старый снимок имён его не включил. Title pending уже останавливает обычные кадровые повороты до обработки поиска; перед выстрелом дополнительно проверяется, что текущая цель соответствует Special focus. При выборе между несколькими именованными Special в ограниченной области сначала открытые, затем ближние, затем стабильный ID. Это НЕ определяет владельца Special.

Ручное вмешательство во время Special теперь делает локальную паузу вместо `disable()`: сохранённый master не выключается, нужен новый намеренный старт. Поиск/движение/выстрелы останавливаются; автоматического возобновления нет.

## Диагностика

Combat → «Подробности выбора целей» и «Скопировать диагностику Combat».

`TargetDiagnostics` хранит только последний поиск: счётчики всех рассмотренных кандидатов и максимум12 приоритетных строк. Состояние удержания/ожидания обновляется отдельно, возраст последнего поиска показывается явно. Это не бесконечный журнал и не постоянно обновляемый полный список всех мобов. Открытие меню сбрасывает активную клавишу как раньше, но последний снимок остаётся доступным.

Причины: выбран; ожидает результат; подходит, но сравнивается оценка; закрыто тело; внеFOV; вне локального радиуса; фильтр; приоритетSpecial; недоступен. Для подходящих строк показывается категория цепочки. Живой захват отдельно объясняет, почему более удобные кандидаты не переключают его.

Отчёт содержит версию, общий тип профиля (zealots/custom), режимы, безопасные числовые пороги/флаги, камеру и этот снимок. Ник/чат/координаты/адрес сервера/имя своего профиля/произвольные фильтры/содержимое конфигурации не читаются в отчёт. Строки мобов: только канонические Zealot/Bruiser/Special либо translation-key вида сущности, НЕ custom name таблички. Никакой отправки по сети: только по явному нажатию в буфер обмена.

`aimDiagnostics` — общий переключатель отображения, не параметр боевого пресета. `aimChainRearWaitMs` — параметр боевого пресета, старым снимкам добавляется350 независимо от ранее выбранного профиля.

## Пользовательская приёмка

1. Несколько видимых соседей: выстрел → следующий локальный, без дополнительной паузы, пока есть свободные близкие.
2. Локальные уже выстрелены, остались только дальние/сзади: короткое ожидание; новое появление близкой цели немедленно делает её кандидатом. При0 ожидания нет. При истечении лимита fallback разрешён.
3. Выживший предыдущий моб движется: группа считается относительно актуального якоря; смерть/удаление не порождают фиктивное подтверждение убийства.
4. Special появляется во время обычного боя/ожидания: нет обычного выстрела по старой цели после начала Special-обработки; Special получает приоритет. Частичное укрытие изalpha.2 сохраняется.
5. Ручная мышь/кнопка во время Special: остановка, master остаётся разрешённым, продолжение только новым стартом.
6. Профили сохраняют разное ожидание; остальные настройки не сбрасываются.
7. После отказа открыть настройки и скопировать отчёт. Проверить причину и возраст снимка, отсутствие приватных строк.

Агент выполняет только компиляцию и статическую проверку. Minecraft, сервер, тесты, stress, симуляции, бенчмарки и GUI-стенды не запускаются. Прямого переноса Aether в этом пакете нет; GPL-совместимое заимствование остаётся допустимым для подходящих следующих задач.
