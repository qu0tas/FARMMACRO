# Воспроизведение игрового прогона

Отдельный локальный vanilla-сервер 26.1.2 + Fabric-клиент. Тестовый entrypoint существует **только при `-PnavTest`**, код из `src/navTest` в обычный JAR не входит.

**Арена очищает/ставит блоки командами и телепортирует/убивает тестового игрока. Не подключать к своему миру, Hypixel или любому публичному серверу.** Сервер слушает только 127.0.0.1:25567, используется отдельная папка `run-navserver/navworld`. `online-mode=false` нужен только для локального offline-аккаунта NavTester. Не открывать порт наружу.

Нужны Java 25, графическая среда/OpenGL, доступ к Gradle-зависимостям/vanilla assets и согласие с EULA Minecraft. Подготовительный скрипт записывает `eula=true`, конфиг отдельного сервера и его локального оператора; запускайте только при согласии с EULA.

```sh
python3 tools/navigation/prepare_local_test.py
# Терминал 1:
./gradlew -PnavTest runServer --no-daemon -Dorg.gradle.jvmargs=-Xmx256m
# Дождаться Done в журнале сервера. Терминал 2:
./gradlew -PnavTest runClient --no-daemon -Dorg.gradle.jvmargs=-Xmx256m
```

На Linux без физического экрана можно использовать Xvfb и Mesa, например DISPLAY=:98 LIBGL_ALWAYS_SOFTWARE=1; это не проверка производительности на игровой видеокарте. Нужна память одновременно под клиент, сервер и два небольших процесса Gradle. Тестовые клиент/сервер ограничены 768/512 МБ heap.

Результаты: `run-navclient/navtest-results.txt`, скриншоты `run-navclient/screenshots/navtest-*.png`, журналы клиента/сервера. Ожидаемые отказы тупика/телепорта/смерти — PASS только при корректном Status.FAIL. Во время сценариев нельзя двигать мышь/нажимать игровые клавиши. Один изменяющийся координатный goal — не тест реального песта.

Сценарии: открытый участок, стена/углы, коридор шириной 1 блок, одиночный блок, несколько препятствий, подъёмы, тупик, динамическая блокировка, остановка, телепорт, обновление цели, 8 последовательных отрезков, смерть. Масштаб GUI переключается 2→3; проверка отображения пути включена со второго сценария.

Для дистрибутива обязательно заново выполнить **без `-PnavTest`**:
```sh
./gradlew clean build routeStress
```
Не отдавать тестовую папку клиента/мира или обработанный с тестовым entrypoint `build/resources/main/fabric.mod.json` вместо обычного JAR.

Дополнительный обязательный подъём: запустить клиент с `JAVA_TOOL_OPTIONS=-Dfarmmacro.navHeightOnly=true` и теми же аргументами Gradle. В этом режиме единственная цель стоит на верхней платформе (Y=66), обойти всё по земле и получить PASS невозможно. Для этого режима файл результатов содержит одну строку; основной прогон сохраните до запуска.
