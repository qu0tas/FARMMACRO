# K2-006 / alpha.12 — фермерские схемы

**Код реализован; пользовательская игровая приёмка НЕ пройдена.** MC26.1.2 / Fabric0.19.5 / API0.155.3+26.1.2 / Loom1.18.3 / Java25.

## Сравнение и решение

Read-only reference: https://github.com/mizly/aether/tree/34d3b894d407fe06a5ba1e822f0616f17beccd7b/src/main/java/dev/aether/macro/farming (tag1.3.1-r6, GPLv3). Сравнены ADFarmMacro, WSFarmMacro, SShapeCropMacro, SShapeSugarCaneMacro, SDSMushroomMacro, CocoaBeansMacro, CustomFarmMacro. Код/ассеты не копировались и не адаптировались: собственная геометрия и существующий исполнитель Kaelix.

| Область | Aether: подход | Kaelix K006 |
| --- | --- | --- |
| A/D, W/S | Цикл направлений с default angle | Длинные отрезки A/D или W/S, длина/число/переход задаются пользователем. 0переход — обратный ход по тому же отрезку |
| S-shape | Поперечные ряды + switching lane, optional Hold W | Чередование заданных клавиш/противоположных, переход отдельным отрезком безатаки. WA/WD действительно меняют координаты геометрии |
| Тростник | Чередование A/S и диагональный угол | A/S геометрические участки; рекомендуемый взгляд под конкретный билд задаёт пользователь. По умолчанию без отдельного перехода; его можно явно добавить |
| SDS-грибы | A → S → SD, зеркальная версия D → S → SA | Длинный A, короткий S по laneSpacing, длинный SD, снова A. Зеркало A↔D. Это не детектор стен/конца любого SDS-билда |
| Какао | W → D → S → D и собственный pitch | W/S длинные участки, D короткие переходы, pitch пользователем под стену/инструмент |
| Custom | Пользовательские waypoints/keys/angles/radius/confirm delay | Прежние точки/паузы/actions/drop/jump/slot + farmKeys/farmTurn, без нового формата записей/второго scheduler |
| Подготовка/возврат | Начальное выравнивание/waypoint/startspawn | Прежний countdown/Mousemat/ReturnWalker/RouteEnd. Отдельный opt-in literal /setspawn, без broad teleport allowance |

**Существенное отличие:** это не перенос Aether collision-driven farming state machine. Конструктор задаёт явный путь. Нужны известные размеры/взгляд и проверка точек на своей ферме; wall/radius/keys не догадка о произвольной чужой конструкции. Custom позволяет поправить шаблон. Старые варианты не удалены, выбор дизайна после пользовательского теста.

## Где найти / как подготовить

1. Сохрани текущий маршрут обычной кнопкой. Освободи буфер редактора только после сохранения.
2. Маршруты → «Фермы: конструктор схем». Встань у начала на опоре, выбери пресет, взгляд, длину/ряды/переход. «Взять текущий взгляд» не вращает существующие точки.
3. «Создать схему здесь» работает только в пустом буфере, при остановленных макросах/записи, с игроком в мире. Генерация ничего не запускает, не пишет/удаляет старые route-файлы. Сохрани результат обычным Save.
4. Редактор позволяет менять точки/паузы/клавиши/действия/слоты. Параметры отрезка относятся ОТ текущей точки ДО следующей. Настройки runtime схемы — ⚙ маршрута; для Custom достаточно включить фермерский режим на обычном маршруте. Клавиши «Авто» используют WalkCore.
Ручной зажим L / пользовательский WHOLE-hold могут явно перекрывать действие участка; для шаблона оставь их выключенными, иначе утверждение «без атаки на переходе» не относится к такому переопределению. Это старый совместимый механизм, не скрытый новый attack toggle.

5. Обычные Start/End/Continue и GUI; отдельной конфликтующей глобальной клавиши нет. Переназначенные игровые W/A/S/D и обычные бинды Kaelix сохраняются.

## Исполнение / invariants

- MacroSettings.farm disabled default; ModConfig.farmBuilder только шаблон конструктора. Copy/sanitize/refresh/fromFile включают новые поля. PointRoutev7, farmKeys/farmTurn имеют безопасные defaults. v1–6 не переписываются сами, старые записи не мигрируют в схему. Defaults новых маршрутов не распространяют enabled farm на записи.
- Один SourceKind.ROUTE, тот же RouteWalker и WalkCore. FarmRuntime — adjunct: подготовка/проверка/предпочтительные клавиши, не собственный playback или lease. Прежний NavigationInput защищает подходы/возврат. Пока он занят, фармерский executor не нажимает кнопки.
- Идеальная геометрия включённой фермы не деформируется случайными альтернативами/route-shaper/Look. Углы выбираются один раз на проход (yaw±≤2°, pitch±≤10°); поворот SmoothTurn конечный, без бесконечного покадрового random и без raw position/velocity/ability changes. Привязка CameraBinding приоритетнее углов схемы.
- Уже имеющийся Squeaky Mousemat в startup не дублируется; ожидание≤240ticks. Camera alignment≤200ticks, затем понятный стоп. Подготовка/три стабильных тика без движения/атаки. Freelook/MouseLock мешают этому режиму и дают стоп — снимите их, в том числе mouseLockOnStart.
- farmKeys только предпочтение при dot>.995 и близости к линии. Если изменили геометрию/камеру или игрок сдвинут, WalkCore корректирует направление. Это предотвращает слепое движение по устаревшим буквам.
- farmTurn добавляет switchPauseTicks при достижении точки внутри WalkCore; базовый pauseTicks в файле/active-copy не изменяется. Resume и сохранение не накапливают паузы. Fast switch defaultOFF: нет только добавочной паузы, radius+0.12 до0.45; ручная пауза остаётся. Протестировать края перед включением.
- XZ bounding box актуальных точек + margin. Для обычных плоских участков GroundProbe проверяет ограниченный live sweep/support/hazards, не только центр блока. Dedicated jump/drop/action/height change остаются собственным контроллерам. Локальные двери/обход/лестницы доступны через общую навигацию/пользовательские точки, конструктор не перестраивает сам произвольную ферму вокруг стены.
- Для нормального фарм-отрезка независимый best-distance progress timeout100ticks (~5с), без слепого обратного прыжка старого antiStuck. Выход за bounds/нет опоры/закрытый или неизвестный коридор — стоп с причиной и ручным запуском. Support probe консервативен; вода/тонкие опоры/необычный билд могут быть отвергнуты вместо рискованного движения.
- Неподходящий server/world/dimension — отказ. Далеко от начала — обычный ReturnWalker при включённом возврате, без fallback «начать вдалеке». Если конец круга не у начала — ReturnWalker после RouteEnd/Rewarp, а не длинный слепой зажим A/D. Общие planning budgets/cache/live checks/manual cancel сохраняются.
- /setspawn только явный opt-in, literal command, один запрос на новый ручной run у начала на земле с connection, не resume и не повторные круги. Серверный ответ/право команды **не подтверждены** самим фактом отправки. Не добавлен общий teleport bypass и новые команды возврата.
- Паника/GUI/мир/нет фокуса/lease не запускают новый фарм/чат/return. Ручная физическая мышь/движение отменяют схему, не master разрешение других функций. Фермерские Shift/Sprint идемпотентны и при toggle controls; записи не менялись.

## Проверка в этой работе

Только статическое чтение исходников/референсов/API26.1.2, `git diff --check`, `gradlew jar`, проверка состава и байтов JAR/ZIP. Никакие Java mod classes не исполнялись для проверки поведения. **НЕ запускались Minecraft, клиент, сервер, unit/integration/stress tests, симуляции, benchmarks, GUI harness.** Кодовая завершённость не означает готовность любого шаблона к твоему Garden.
