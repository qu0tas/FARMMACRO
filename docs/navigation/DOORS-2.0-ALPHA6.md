# Alpha.6 — дверные взаимодействия и ввод

**Тестовая alpha, пакет K2-004/4b; не полный 2.0.0.**

- Новый общий NavigationDoor вместо удержания обычного ПКМ. Дверь/калитка выбирается только при пересечении её коллизии ближайшим коридором тела на пути, а не просто потому, что стоит рядом.
- Наведение на видимую часть реальной формы выделения, включая обе половины двери; выбранная доступная точка удерживается. Не центр пустой клетки. Вокруг угла/вне досягаемости продолжается подход, а не ранняя остановка для бесполезного ПКМ.
- Одиночный vanilla useItemOn только по свежему лучу фактического взгляда, по той же двери и в пределах min(3бл, разрешённой игроку дальности). Нет generic useItem/очереди ПКМ/удержания кнопки; слот не меняется. Серверные плагины всё равно определяют последствия взаимодействия.
- До3 взаимодействий с одной дверью за текущий подход, пауза10тиков; общий срок100тиков на эпизод. Последняя попытка получает окно ожидания. Краткий откат предсказанного открытия сервером не обнуляет бюджет. Открытое состояние ждём3 наблюдения: это debounce, НЕ доказательство серверного подтверждения. Замена блока/потеря видимости/недоступный чанк дают понятный стоп.
- На время владельца ReturnWalker MouseHold не подмешивает зажим, а ЛКМ/ПКМ навигации отпускаются без отложенного release. При получении/освобождении управления отменяются только ворота кнопок HandDelays; профили/настройки/модель задержек/тайминг слота не сбрасываются.
- Счётчик застревания на лестнице сбрасывается для каждой новой climb-точки: новая высота не сравнивается с лучшей ошибкой предыдущей. Полный контроллер лестниц ещё впереди.
- Подъёмы/прогресс/toggle Shift/Sprint alpha.5, B-передача, бинды, Combat и Alpha-песты сохранены. KeyAuth не добавлен. Форматы маршрутов/конфигов не изменены.

**Только статический просмотр, javap и gradlew jar. Minecraft/сервер/тесты/stress/симуляции/GUI-стенды не запускались.** Колоночный A*, узкие открытые двери, люки, лестничная геометрия и полёт ещё не объявляются готовыми. Код/ассеты Aether не копировались.

## Ограничения и ручная приёмка (только пользователь)

- На своём безопасном участке: деревянная и медная дверь, подход с двух сторон, верхняя/нижняя половина, калитка, нижний проход под потолком. Должен открыть либо дать ограниченный отказ. Железные двери не считаются открываемыми рукой.
- Дверь сбоку от пути не должна отвлекать. Дверь за углом — сначала подход. За стеной не должно быть взаимодействия. Уменьшенная дальность игрока не обходится; поиск формы может консервативно не найти маленькое видимое окно.
- При запрете/серверном закрытии: не более3 взаимодействий на корневую дверь за текущий подход, включая после краткого client-open. Новый явный запуск обнуляет бюджет; перепланирование того же подхода не обнуляет. Максимум64 разных взаимодействовавших дверей на подход. Не подходит для маршрута, который намеренно многократно открывает одну дверь.
- Ожидание100тиков — срок эпизода, не гарантия5 реальных секунд при задержке клиента.3 открытых наблюдения не доказывают приём пакета сервером. Сервер может закрыть позже; реальные коллизии/застревание и ledger ограничивают последствия, но прохождение не гарантировано.
- Потеря видимости активной двери: максимум20тиков ожидания; замена блока/выгрузка — стоп. Меню/фокус/паника/End/смена мира прекращают подход прежними guards. Клиент не ломает блоки, не меняет физику/режим/слот. useItemOn идёт обычным игровым путём; сторонние плагины могут запускать собственные действия, абсолютной гарантии отсутствия способности оружия нет.
- Включённый ручной MouseHold и макросный hold не должны включать ЛКМ/ПКМ в процессе подхода или поиска пути. Настройки не удаляются. При продолжении штатного источника его hold может снова действовать: это не автоматическое возобновление после паники.
- Несколько последовательных climb-точек: baseline каждой новый. Это только исправление счётчика, не обещание подъёма по всем лианам/лестницам/лесам.
- Проверить регрессии alpha.5 (ступени/прыжок/двухблочный спуск/toggle), alpha.4 (B/бинды/контексты), Combat. Песты остаются Alpha.
