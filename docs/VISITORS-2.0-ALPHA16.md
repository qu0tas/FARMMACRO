# Визиторы Garden · K2-010 · Alpha16

**Реализация для известных форматов готова, игровая приёмка не пройдена.** Это не стабильный 2.0.0. Агент не запускал Minecraft, сервер, тесты, stress, симуляции, benchmarks или GUI-стенды. Скомпилирован JAR; применимость реального протокола/меню проверяет пользователь.

## Начальная настройка

1. Сохрани копии `config/farmmacro.json`, `config/farmmacro_routes` и `config/farmmacro`. Удали предыдущий JAR FarmMacro/Kaelix из `mods`, поставь только один новый JAR. Minecraft26.1.2 / FabricLoader0.19.5 / API0.155.3+26.1.2 / Java25.
2. Открой **Визиторы · Alpha**, включи только общее разрешение. Авто, закупки, выдача, отказ, компакторы, Tip Jar и продолжение фермы изначально OFF. Не включай всё разом до проверки.
3. В Garden встань **на землю рядом с визиторами сарая** и нажми «Запомнить точку сарая». Сохраняются координаты, сервер и измерение. Автоматического определения планировки сарая нет. После переноса сарая/смены профиля запиши точку заново. Scope не является надёжным идентификатором Hypixel-профиля.
4. В Tab должен быть стандартный английский блок `Visitors: (N)` с 0–5 именами подряд. Сначала попробуй ручной старт при открытой очереди. Незнакомая редкость/неполная очередь не угадываются. Реальный порядок Tab повторяет проверенную сортировку26.1.2 (listed players, tab order, spectator, team, case-insensitive name).
5. Нужен пустой слот хотбара. Либо включи «Настроенный предмет в руке» и запомни предмет с точным SkyBlock ID/опциональным UUID. Дубликаты без UUID и отсутствие предмета останавливают. Не используй культуру, которую визитор потребует. Из обычного инвентаря ничего не перекладывается. Выбор слота локальный + обычный пакет, без выдуманного server ack.
6. Старт/отмена — кнопкой или назначенной тобой клавишей «Визиторы: запуск / отмена (Alpha)» во вкладке **Клавиши**. По умолчанию она не назначена; всего27 биндов. End и ручное управление прекращают операцию.

## Очередь, фильтры, автоматический запуск

- На запуск фиксируется до5 имен из Tab. Повторно тот же NPC в рамках запуска не добавляется. Подход только к уникальному загруженному NPC у записанного сарая (радиус24); отдельная стойка-метка связывается с телом, по самой метке не кликает. Реального online-игрока из списка игроков не выбирает. При неоднозначности/потере — стоп.
- Приоритет: точный **Ignore** → точный **Reject** → политика редкости. Имена разделяются `;`, регистр учитывается. Spaceman по умолчанию Ignore. SERVE — обслужить; SKIP — оставить стоять; REFUSE — отказ только при отдельном разрешении. Неизвестная редкость — SKIP, если имя явно не внесено в Reject.
- Разрешения «выдавать», «отказывать», «покупать» независимы. При нехватке предметов и выключенных покупках NPC пропускается; вещи не выдаются частично. Выдача расходует и **ранее имевшиеся** культуры, не только приобретённые модом.
- Авто отдельно OFF, только при фактическом сборе активной фермерской схемой, порог1–5, стабильная очередь40тиков, ≥30секунд между автоматическими запросами. Одна попытка на состав очереди; повтор допускается после его изменения/снижения ниже порога/смены мира, но не бесконечно на одной ошибке. Ручной запуск остаётся явным действием.
- Jacob по умолчанию пропускается, если sidebar содержит `Jacob's Contest`. Если распознанный конкурс начался во время сервиса — остановка, не автоматический возврат. Другой язык/новый формат не обещаются.
- Пауза допускается для маршрута фермы, но не для записи/Combat/пестов/другой автоматики. Общие ввод/камера и ReturnWalker переиспользуются; второго пути/движка движения нет. Дальние участки≤24бл только через уже существующий проверяемый полётный коридор. Новых warp-команд и исключений телепорта нет.

## Бюджет закупок

По умолчанию закупки OFF. Настройки стартуют с лимитов100000coins/визитор,500000coins/запуск,100000coins минимального остатка и10000 закупочных coins/Copper. Проверь и поставь собственные лимиты перед разрешением. `0` запрещает соответствующий расход, а не отключает ограничитель.

Поддерживается только локальный allowlist39 точных официальных ID/названий культур/переработанных продуктов (`assets/farmmacro/visitor-products.json`). Это **не все требования всех визиторов**. Неизвестное требование/пустая/дублированная строка/неизвестный Copper останавливают до выдачи или закупки. ID не выводится из произвольного имени.

До финансового клика нужны одновременно:

1. Собственное ожидаемое меню после `/bz <точное имя из каталога>`, точный товар и пустой подтверждённый курсор. Обычные слоты инвентаря не нажимаются.
2. Нефинансовый `Custom Amount` с `Click to specify!`: только этот известный opener таблички. Пресеты1/64 не нажимаются — они могут сразу купить. Неизвестный opener — отказ.
3. Собственная табличка количества в коротком окне; ввод только необходимого числа. После неё — свежая серверная котировка. Никаких GUI/key injection в чужую табличку.
4. Полные точные товар, `Amount: Nx`/`Amount: N`, `Price: ... coins` и `Click to buy now!` в lore одного известного control. Per-unit/NPC/сокращённая `k/m` цена не заменяет итог. Чужие предупреждения/Buy Anyway не подтверждаются.
5. Консервативный **невозвратный резерв до клика**: общий coins на визитора/запуск; закупки/Copper; исходный Purse минус предыдущие резервы; актуальный наблюдаемый Purse; минимальный остаток. Цена округляется вверх, баланс вниз. Coins/Copper — именно расход закупок, НЕ рыночная оценка уже имевшихся предметов.

Финансовое подтверждение нажимается один раз. Повторного клика из-за лага/непришедшего результата нет. Успех требует собственного активного запроса, точной системной `[Bazaar] Bought Nx Name for ... coins!` с расходом≤резерва **и** нового обновления серверного инвентаря с прибавкой нужного ID. Игровой/обычный чат/actionbar не подменяет квитанцию. Предметы или баланс, изменившиеся извне, не служат поводом снять лимит.

**Граница гарантии:** это лимит по **наблюдаемой котировке до клика**, а не передаваемый серверу `maxPrice`. Обычный контейнерный клик не предоставляет атомарной цены/баланса. Изменения сервером между показом и обработкой исключить нельзя; квитанция сверх резерва отменит последующие действия, но совершённая на сервере покупка не откатывается. Не обещаем невозможного «никогда не потратит больше при любых изменениях сервера». При неизвестном формате финансового клика вообще не будет.

Возможна частичная закупка нескольких требований до ошибки на следующем. Она остаётся в инвентаре. При таймауте резерв не возвращается и повторной покупки в том же запуске нет. Лимит «на запуск» сбрасывается только новым явным/допущенным автоматическим запуском, не является общим дневным лимитом.

## Подтверждение выдачи/отказа

Перед Accept повторно совпадают требования и Copper, всё количество уже есть, сервер показывает известный `Click to give!`, цель и редкость ещё присутствуют в Tab. Предмет руки не может входить в требования. Для успеха нужны собственный клик + точный `OFFER ACCEPTED with Name (RARITY)` + новый состав Tab без цели + новое обновление инвентаря с расходом требований. Исчезновение само по себе не выдаётся за успех.

Refuse — отдельный точный control и наблюдаемое изменение очереди; не считается принятием. Неизвестные NPC/меню/редкость/сообщения/требования не заменяются слепым слотом29/33 и не угадываются по соседним игрокам.

## Компакторы и Tip Jar

- Personal Compactor4000/5000/6000/7000 — точные SkyBlock ID, только хотбар. Если найден в обычном инвентаре при разрешённом обслуживании, остановка с просьбой переложить вручную. Вещи не таскает.
- Только известный Personal Compactor UI и control `Compactor Currently ON/OFF` с опциональным `:`. Один toggle, затем новое серверное значение. Перед toggle сохраняется запись возможного OFF; даже если disconnect придёт раньше ack, запись не потеряется.
- Изначально OFF не включается после штатного сервиса. Восстанавливаются только собственные записи изменений. UUID используется если есть, иначе точный ID@исходный хотбар-индекс — это слабее UUID и не доказывает тождество при замене другим одинаковым предметом.
- Паника/отмена не открывают меню и не включают компакторы автоматически. HUD/GUI показывают pending. Верни те же предметы в исходный хотбар, нажми «Восстановить записанные компакторы» либо включи их вручную и затем кнопкой подтвердись по ON. Запись снимается только после наблюдаемого ON. Ручное восстановление не продолжает ферму.
- Tip Jar отдельно OFF. Наведи прицел на сам горшок и запомни его кнопкой. После изменения сервера/измерения точкой сарая старая запись jar инвалидируется. При смене профиля/перестройке запиши обе точки заново.
- Нужны точный сохранённый FlowerPotBlock, близкая метка `Fungal Tip Jar`, отдельный счётчик `Copper: n / capacity`, реальная видимость блока, дистанция и **пустая рука** (не сажает растение/не использует оружие). Один `useItemOn`; результат только при уменьшении счётчика. Произвольный ближайший горшок не выбирается. Новый/иной формат останавливается, не считается успехом.

## Остановка и возврат

Всего60–600секунд (настраивается), дополнительные таймауты этапов,≤90 меню-кликов,≤40 участков пути на цель. Открытие своего GUI ожидается≤2.5секунд и только нужного вида/заголовка; это не глобальное разрешение чужих окон. Packet-only копии slot/content/cursor отделены от predicted menu, финальный клик сверяет их с действительным контейнером. Курсор не выбрасывается/не очищается обманом.

End, ручная клавиша/клик/скролл, мышь в мире, чужое окно, смена мира/фокуса, паника, таймаут, пропавший предмет или другой владелец управления прекращают сервис. Никаких дальнейших покупок/приёмов/автоотката/возобновления после этого. Открытое меню/курсор проверь вручную. Купленное и уже выданное не откатываются. Список сомнительных компакторов сохраняется.

Только штатное завершение ведёт назад к исходной позиции/камере/позе полёта, с возвратом исходного хотбар-слота. Resume отдельно OFF. Он разрешён только прежней приостановленной ферме, тому же миру/ревизии/сохранённому источнику, исходной идентичности руки, успешному возврату и восстановленным компакторам. Если исходный полёт исчез — стоп. Combat/новая ферма сами не запускаются.
