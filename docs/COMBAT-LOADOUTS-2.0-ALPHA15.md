# K2-009 · Combat-профили и глобальные лоадауты

Версия **2.0.0-alpha.15**, Fabric / Minecraft 26.1.2 / Java 25. Код реализован; игровую приёмку проводит пользователь. Это не стабильный 2.0.0.

## Combat-профили

Вкладка Combat → Профили. «Зиалоты» — сохраняемый базовый профиль с собственной группой каталога, не весь Enderman Slayer. Сохраняются 45 параметров: фильтры/имена/локация, камера и скорости, Human-настройки, момент выстрела/очередь, осмотр, A/D, подсветка и связанные ограничения. Разрешение aim, Hold/Toggle/бинд, диагностика и Combat-паника остаются общими. Автовыстрел реализован только для Glacial Scythe; другим оружиям не приписывается адаптер ближнего боя.

- **Копия текущего** оставляет все параметры точной копией. **Новый из зиалотов** наследует настройки, но очищает список мобов и отключает специфичный Special/Zealot приоритет; выбери цели в каталоге.
- Имя до 40 символов; до 24 профилей. Базовый Zealot удалить нельзя. Удаление своего выбирает Zealot.
- **Сброс выбранного** затрагивает только его; автопальба/A-D выключены. У своего профиля список мобов становится пустым и выбранный фильтр включён, пока не выбраны цели.
- **Экспорт** копирует только выбранный профиль с префиксом `KAELIX-COMBAT1:`. **Импорт** читает буфер и добавляет новый профиль с новым ID, не перезаписывая существующий. Полный `KAELIX1:` конфиг сюда не подходит. Список допустимых полей, типы и размеры проверяются; неизвестное поле — ошибка. Экспорт/импорт не меняют панику, клавиши, разрешение aim или лоадауты.
- После смены/сброса/импорта требуется собственное новое нажатие aim. Импорт не отправляет буфер в чат и не включает автоматику.
- Старый профиль с неполными полями получает собственные defaults, а не значение прошлого выбранного. Старый Slayers-каталог других профилей не заменяется на зиалотов.

## Глобальные лоадауты

Новая вкладка «Лоадауты». Есть Mining, Combat, Foraging; свои копии — до 12. Действия задаются вручную и выключены по умолчанию. Это композиция собственной руки + Wardrobe + Pets + настроек Combat, **не нативный серверный `/loadout` адаптер**.

1. Сначала включи «Разрешить лоадауты» и выбери запись.
2. На нужном сервере нажми **Запомнить сервер**: сохраняются точные сервер и измерение. На другом сервере/измерении запрос отклоняется. Эти значения локальны, не входят в Combat-экспорт.
3. Для руки возьми нужный SkyBlock-предмет и нажми **Запомнить текущий предмет**. Сохраняются ID/UUID, а не только название. Включи соответствующее действие. При применении предмет должен находиться в хотбаре; дубликаты без различимого UUID отклоняются. Не перекладывает из инвентаря, не покупает и не выбрасывает вещи.
4. Для брони включи Wardrobe и выбери слот 1–18 с уже сохранённым комплектом. Пустой/заблокированный слот не используется. Точный формат меню `Wardrobe (1/2)` / `(2/2)`, известная однозначная кнопка страницы и Slot с known ready/current lore обязательны.
5. Для питомца включи Pets и введи точный вид без `[Lvl N]`. Питомец должен быть на видимой странице. Если одинаковых несколько, укажи точный UUID из доступных данных (ExtraAttributes uuid или petInfo). Не угадывает редкость/уровень и не листает неизвестные страницы Pets.
6. При необходимости свяжи Combat-профиль. Это только применение настроек, без изменения aim permission/клавиши и без запуска Combat.
7. **Применить / остановить** закроет GUI и поставит ручной запрос. Или назначь новый бинд во вкладке «Клавиши»: по умолчанию он не назначен. Активные ферма/Combat/песты, ручные движения/кнопки, другой владелец ввода или pending panic блокируют начало. Нажатие бинда во время операции отменяет её.

Порядок: броня → питомец → рука → настройки Combat. Отдельные действия можно отключать. При успехе только локальное уведомление. **Не запускает и не возобновляет прошлую автоматику.** При частичной отмене уже применённая броня/питомец/рука не откатываются: проверь их вручную.

### Подтверждение и ограничения

- Wardrobe/Pets читают отдельные копии новых server slot/content/cursor пакетов, а не локально предсказанную анимацию клика. Тот же screen/menu/container, ожидаемая кнопка, пустой курсор и новый active/current lore обязательны. Если целевое уже активно, это определяется по загруженному серверному описанию.
- Выбор хотбар-слота не имеет отдельного server acknowledgement. Мод проверяет локальный слот/ID/UUID три тика и отправляет обычный пакет. Статус прямо говорит об этом ограничении — это не выдуманный server ack.
- Максимум 20 секунд/400 тиков на операцию, 4 секунды на шаг, 4 клика и 1 переход страницы Wardrobe. Ожидание собственного меню — 2 секунды. Неизвестное меню/описание, отсутствие ack, курсор с предметом, пропавший/дублированный питомец/предмет — остановка, не повторные слепые клики.
- Ручная клавиша, клик, скролл или мышь в мире, End, паника, внешний слот/предмет, серверное перемещение, смена мира/потеря фокуса и чужое окно отменяют операцию. Локальная смена руки использует существующий expectSlot, не отключая детекторы глобально.
- После остановки собственное открытое меню может остаться игроку. Предмет на курсоре нужно вернуть самостоятельно: мод не делает THROW/внешний клик, не чистит курсор и не перекладывает предметы.
- Новые/локализованные меню и серверные варианты lore требуют отдельного адаптера по твоим данным. Универсальная совместимость не заявлена.

## Авто по локации — всё OFF

Нужны одновременно: общий разрешитель лоадаутов, «Разрешить авто», авто у выбранной записи и сохранённые сервер/измерение. В поле локаций укажи точные строки sidebar через `;`, например `The End;Dragon's Nest`. Цвета/символы оформления очищаются, затем сравнивается вся строка без учёта регистра, не подстрока из чата.

После 60 стабильных тиков (около 3 секунд) совпадения и при свободном вводе допускается одна попытка. Две подходящие записи запрещают автоматический выбор. Между автоматическими запросами минимум 10 секунд. Ошибка/отмена не вызывает повторов в той же непрерывной локации: надо выйти из условия и войти снова или применить вручную. Переход между записями/миром начинает новое условие. Никакой смены снаряжения посреди активной фермы или Combat.

## Проверка пользователем (не выполнена агентом)

- Сохрани разные камеру/мобов/выстрел/A-D в двух профилях; переключи туда-обратно и перезапусти клиент. Проверь точную копию и reset только выбранного.
- Экспорт одного, импорт нового; неверная строка/полный конфиг/неизвестное поле должны отклоняться без замены текущих настроек. Panic/keybind/aim permission не меняются.
- Открой все 12 вкладок и поиск; новый бинд должен быть в каталоге 26 клавиш и не назначен изначально.
- Сначала пробуй по одному действию: только рука, только уже активный/другой Wardrobe, только питомец. Затем сочетание. Проверь страницу Wardrobe 2, дубликаты/UUID/неизвестное lore/отсутствующее меню и отмену.
- Проверь, что собственная смена руки не создаёт ложную панику, а внешние изменения не получают общей поблажки.
- Авто включай последним: точное условие, два совпадения, уход/возврат, ошибка без цикла повторов, активный Combat/ферма не прерываются ради лоадаута.

## Источники и сравнение

- Wardrobe: https://wiki.hypixel.net/Wardrobe — существующие комплекты, страницы и ready/current/empty состояния. Формат текущего меню всё равно нуждается в проверке пользователем.
- Aether GPLv3, tag `1.3.1-r6`, commit `34d3b894d407fe06a5ba1e822f0616f17beccd7b`, `modules/gear/helpers/LoadoutManager.java`: изучены приоритеты/таймауты/завершение. Там native `/loadout`, фиксированные GUI-слоты, generic equipped chat и возврат к ферме; здесь независимая реализация Wardrobe/Pets без этих предположений. Код/ассеты не копировались и не адаптировались.
- Точные MC26.1.2 API проверены `javap` по локальному game jar: `ServerboundSetCarriedItemPacket(int)`, `handleContainerInput`, `ItemStack.matches`, `MouseHandler.onScroll(JDD)`, уже интегрированные slot/content/cursor hooks.
