# Kaelix Motion — alpha29 / этап B2 (B1 сохранён)

## Как включить
Меню → Kaelix Motion → Движок Motion → **Aether / отдельный**. Только после остановки макроса, записи, навигации и текущего поворота. Наш Kaelix остаётся по умолчанию: никакой миграции персональных диапазонов/боевых профилей. Пресет Aether применяется явно селектором; после ручных изменений его имя — имя последнего применённого шаблона, не утверждение побайтного совпадения.

## Что действительно подключено
| Потребитель | Kaelix | Aether в B2 |
|---|---|---|
| Поворот к пресету через SmoothTurn | прежний MouseTurn/плавный | RotationManager-style timing/easing + GCD |
| Камера фермерской схемы | прежний диапазон схемы, один угол/проход | собственные диапазоны Aether, один угол/проход; default0/0 |
| Следование камеры навигации | прежний TrackingTurn | непрерывное экспоненциальное закрытие ошибки, процентный шум шага, без перезапуска от каждой новой цели |
| Паузы фермерского маршрута | новый отдельный диапазон Kaelix80–240мс | upstream lane-switch диапазон выбранного пресета |
| Остановка/посадка на этаже | общий новый диапазон150–350мс | то же расширение Kaelix, не выдано за upstream-функцию |
| Старый Humanizer маршрута | сохранён | не создаётся, чтобы не смешивать два режима |
| Запись | собственный старый Humanizer | не переводилась на новый движок |
| Combat | независимый выбор в боевом профиле | существующий AetherTrackingTurn alpha24; новый Motion его не подменяет |
| CameraBinding точек | мгновенная привязка | плавный маршрутный turn с exclusive ticket, остановкой ввода и подтверждённым углом; final point также ждёт |
| CameraBinding кадров записи | мгновенная привязка | пока мгновенная, свой режим записи сохранён |

Режим не заменяет целиком путь/физику движения, собственные авторские варианты геометрии маршрута и задержки рук. B2 дополняет это владением камерой на время привязок маршрута. Он не переносит интерфейс, сеть, auth, failsafe suppression или все модули Aether. Стоп, сигнал и передача управления не получают дополнительных «человеческих» задержек.

## Адаптация и отличия от оригинала
- Timed rotation: shortest yaw, `max(150ms, randomizedBase, max(abs(yaw),abs(pitch))*msPerDegree)`. Base — целочисленный равномерный диапазон ±15%, как ConfigHelpers. Реальный предел скорости задаёт вызывающий потребитель (скорость схемы/навигации/пресета); новое время — не отмена этого предела.
- Tracking: `1-exp(-dt_ms/trackingMs)`. Новый navigation adapter trackingMs150 — собственный стартовый параметр, не универсальный upstream-пресет навигации. Шум2–6 — **проценты шага**, не2–6градусов. В timed-режиме процентный шум не применяется.
- GCD `(sensitivity*.6+.2)^3*1.2`; delta применяется vanilla `Entity.turn` и существующим `expectTurn`, а не записью позиции, пакетом или обходом детекторов. Нет переноса upstream FailsafeManager.
- Monotonic кадры, dt≤60мс. Собственный остаток субпиксельного шага устраняет преждевременное upstream-завершение при нулевом округлённом шаге на высокомFPS. Завершение только в реальном допуске max(.25°, .51GCD) на каждой оси. У фермерского ожидания учитывается диагональный GCD-допуск, чтобы не ждать бесконечно между пикселями.
- Квантованный угловой бюджет накапливается между кадрами и ограничен60мс скорости: округление не добавляет угловую скорость поверх бюджета. Снимок настроек на поворот; retarget непрерывного слежения не перезапускает весь turn, но сбрасывает устаревший субпиксельный остаток при заметной смене цели.
- Паузы меняются только на копии **нового** прохода схемы. На resume не генерируются второй раз. Прямые промежуточные точки не получают новых случайных стопов; проверяется угол≥25°, farmTurn, drop или переходY>.6. Явные паузы/задержка перед drop/switchPause складывались раньше: новый минимум учитывает их суммарно и не добавляется второй раз. После drop посадочная пауза не сокращается. По требованию игрока всё отключается одним переключателем.
- Старый Kaelix код не удалён; Aether не перезаписывает Combat-профили, запись, radius/геометрию/проверки коллизий. Первоначальный старт по-прежнему только у точки, автовозврат OFF после миграции alpha27.

## B2: привязки к точкам с ожиданием
В Kaelix Motion: **Aether → Плавные привязки к точкам** (по умолчаниюON); скорость120°/с, предел20–360. Применение Normal/Safe/Efficient не сбрасывает этот собственный флаг/скорость. Kaelix и запись сохраняют прежний snapshot, автоматического изменения личных Combat-профилей нет.

1. Tracker маршрута получает одноразовый CameraTurnLease.Ticket. Нельзя перехватить чужой или уже активный поворот; в этом случае локальный стоп, не очередь/бесконечный retry.
2. Пока turn идёт, кнопки движения/прыжка/Shift/Sprint/рук действительно отпущены с учётом toggle-клавиш; MouseHold suspended, отложенные кнопки/слот сброшены. WalkCore, point actions и anti-stuck не продвигаются. На старте слот также ждёт. Физика инерции НЕ подменяется, позиция не записывается напрямую.
3. Завершение анимации переводит ticket в ARRIVED, но НЕ освобождает владельца до проверки фактического yaw/pitch. До ack блокируются чужие SmoothTurn turn/follow, CameraBinding snapshot и NavigationInput.acquire. RecordingSource с привязкой теперь тоже явно сообщает controlsCamera, но его трекинг/кадры не менялись.
4. Контекст должен оставаться прежним: тот же объект игрока и мира, активное окно без меню/паузы, без паники/Freelook/MouseLock/Mousemat/HumanReaction/чужой навигации. Нужна обычная наземная опора (не flying/fall-flying/лестница/вода/лава). Это сознательная граница B2, не новая функция полёта. Сдвиг от начала ожидания более0.75блXZ или0.6блY — отказ. Детекторы паники при этом продолжают работать, не глушатся на весь период.
5. Ожидание ограничено monotonic deadline5–30с по углу, заданной скорости и времени кривой. Timeout/невалидные значения/потеря владельца/неверный итоговый угол/отмена — только локальный стоп. Само по себе `isActive=false` НЕ считается прибытем. Для продолжения нужен новый ручной запуск у сохранённой точки.
6. Ручная мышь (порог перемещения0.7экранного пикселя), движение/прыжок/Shift/Sprint, мышиная кнопка или скролл прерывают только активное ожидание привязки; физическое событие не поглощается. Play на кнопке мыши исключён из дополнительного stop, чтобы общий toggle не запустил только что остановленное заново. Остальная ручная политика мода остаётся прежней. Открытие меню/паника/стоп/выход из мира очищают owned-ticket; аварийный forceStop теперь тоже сначала освобождает ресурсы источника.
7. Для последней точки Aether passDone не обходит ожидание. У старого Kaelix финальный snapshot не добавлялся: его прежняя семантика сохранена.

`BindingQuickCheck` — короткая чистая таблица lease/gate: нельзя украсть/ack чужой или устаревший ticket, cancel не arrival, проверка угла/контекста/сдвига/deadline/NaN, старые defaults/copy/Gson и сохранение opt-out при выборе upstream-пресета. Это НЕ запуск адаптеров Minecraft/реальной физики/миксинов. Их игровая приёмка остаётся за пользователем.

## Проверки и ручная приёмка
`clean build quickCheck`: только сборка и небольшие чистые smoke cases, включая ≤276кадр математического контроллера. Это не модель игры/полёта/стрельбы и не проверка на сервере. Не запускать routeStress/configSweep/soundStress/Minecraft без отдельного разрешения.
В игре сравнить два режима на одной короткой схеме: стабильный pitch на прямой, поворот/этаж/посадка, повторный ручной пуск/stop, разные sensitivity, навигация при явно включённом возврате. Если есть рывок — прислать видео/профиль, не повышать диапазоны вслепую. Автоматизация может нарушать правила сервера; гарантий staff/бан-защиты нет.
