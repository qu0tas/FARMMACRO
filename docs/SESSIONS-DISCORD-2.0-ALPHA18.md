# K2-012 — сессии, перерывы и Discord · alpha18

Код реализован; игровая приёмка НЕ пройдена. Это не стабильный 2.0.0. Существующие 14 вкладок и 28 биндов сохранены; новый HUD — K2-013.

## Сессия: один контроллер

Настройки находятся в существующем разделе автоматизации: расписание, лимиты, reconnect. Единственный Scheduler контролирует живую сессию. SessionLedger — пассивная справка, не второй планировщик.

- Новый принятый ручной запуск начинает новую сессию. Продолжение того же источника после штатного сервиса/перерыва/reconnect не обнуляет суммарные лимиты.
- «Выйти через» — реальное прошедшее время сессии, включая сервисы, перерывы и reconnect/offline. При достижении останавливается автоматика, соединение закрывается, если оно существует.
- Новый лимит работы — накопленное наблюдаемое время PLAYING; 0 отключает. Сервис, ожидание и перерыв не считаются работой. На один тик засчитывается максимум 1 с: длительное зависание клиента не выдаётся за точно наблюдавшуюся работу. Общий срок сессии при этом не теряется.
- Максимум рабочих циклов — отрезки работы расписания, **не круги маршрута**. При достижении стоп до следующего перерыва; 0 отключает.
- Существующий локальный лимит одного запуска не переименован в накопительный. Для суммарного бюджета используй новые настройки.
- Время измеряется монотонными часами живого процесса; изменение системной даты не создаёт новый бюджет. Нет фонового управления после закрытия клиента.
- Выключение/отмена сервиса, исчерпание reconnect, отказ проверки источника или ручной ввод не вызывают автоматический новый запуск. Лимит останавливает сервисы/маршрут/зажим мыши, не выполняет финансовое «исправление» незавершённых операций.

## Перерыв и разрешение продолжения

Перед перерывом существующий менеджер останавливает работу и сохраняет точку. Разрешение продолжения хранится **только в памяти**, содержит отпечаток источника/настроек и контекст. Перед продолжением источник проверяется заново.

Для продолжения требуются тот же источник/конфигурация, совпадение сервера/измерения и известной области, живой игрок, фокус окна, отсутствие меню/редактора/других владельцев управления/паники. Проверяется тип и SkyBlock ID/UUID предмета в руке, положение/полёт; для перерыва также тот же мир, отсутствие снижения здоровья и близкий угол камеры. Число предметов и изменяемый lore не используются как личность инструмента.

Ручной ввод (кнопка, мышь, колесо) во время перерыва отменяет автопродолжение. Панические детекторы сохраняют возможность остановить перерыв. Неизвестный/изменённый контекст = ручной запуск, а не бесконечные попытки.

## Переподключение

- Только разрешённый существующий autoReconnect от действительно работавшей сессии, не от произвольного посещения сервера.
- Ограниченные попытки, задержка/backoff до 600 с, до 60 с на соединение и до 75 с на контекст после входа.
- Команда после входа: пусто, `/warp garden`, `/is`, `/hub`. Старое произвольное значение не исполняется, требуется ручная правка.
- Новая установка: reconnectResume OFF. Старое явно сохранённое true не стирается. Команда возврата может выполняться отдельно от resume, если настроена.
- При resume: минимум 5 с после входа, 20 стабильных тиков, загруженный чанк, покой/рука/источник/контекст. Только один запрос менеджеру; отказ не перезапускает его автоматически. Ранее разрешённый returnAfterReconnect допускает отдельный ограниченный подход после 10 с; не добавляет полёт или телепорт-права.
- **Любая паника отзывает разрешение автоматического reconnect/resume до нового принятого ручного запуска.** Ни ожидание, ни новый JOIN, ни клавиша передачи управления сами разрешение не возвращают.
- Если мир исчез раньше сохранения актуального контекста, используется лишь допустимая сохранённая информация; её несовпадение блокирует resume. Соединение без resume не означает возобновление макроса.

## Локальная история

«Сохранять справку о сессии» OFF. Файл `config/farmmacro/session-state.json`: версия формата, время записи, общий/рабочий/перерывный счётчики, число периодов, фиксированный код состояния. Нет ников/адреса/координат/чата/токена/разрешений управления.

Запись в один IO-поток через временный файл и замену, ожидающие обновления объединяются. Примерно каждые 10 с и при переходах; аварийное завершение может потерять последний checkpoint. Чтение ограничено по размеру/схеме/диапазонам, повреждённый файл не запускает ничего. После рестарта — только справка. Отключение не удаляет прежний файл; уже начатая запись может завершиться. Очистка доступна при включённом сохранении и остановленной сессии.

## Discord: только исходящие уведомления

Мастер остаётся отдельно. Новые уведомления о сессиях, подробности причины, имя сервера, согласие на PNG — OFF. Ранее включённые настройки не сбрасываются скрытно.

- Один сетевой поток, очередь максимум 4; короткие повторы/дубли подавляются. Паника вытесняет ожидающие менее приоритетные сообщения, а не прерывает уже отправляемый запрос. Доставка каждого события не обещается.
- Минимум 5 с между реальными отправками; интервал одинаковых уведомлений настраивается 15–3600 с. Ожидание не блокирует игровой поток.
- HTTP 429 учитывает Retry-After, исчерпанный успешный bucket — X-RateLimit-Reset-After. На ошибки сети/5xx пауза; 4xx требует ручного исправления. Сообщение автоматически не повторяется. Неизвестный результат отправки не объявляется успехом.
- Ручной сброс ошибки/новый URL очищает очередь, но не сокращает объявленную сервером паузу. Выключение/смена настроек/профиля отзывает ожидающие сообщения; уже начатый HTTP-запрос нельзя вернуть обратно.
- Никаких inbound listener, IRC, bot token, удалённых команд, финансовых действий или удалённого resume.

Протокол ограничений: https://docs.discord.com/developers/topics/rate-limits . Сетевые запросы к пользовательскому webhook при разработке не выполнялись.

## Приватность и её пределы

Webhook отдельно: `config/farmmacro/discord-webhook.txt`. Поле показывает маску ID/токена, изменение записывается через временный файл; права 600 там, где ОС поддерживает POSIX. **Это локальный plaintext, не шифрование и не парольный vault.** Не отправляй папку config другим людям. Она исключена из Git; существовавшие ранее отслеживаемые секреты gitignore сам не удалит.

Переносимые профили/коды не переносят локальные флаги Discord/PNG-согласия/сохранения истории. При импорте остаются текущие локальные разрешения. URL и известные текущие/недавние webhook-токены вычищаются из строк переносимого JSON и диагностического текста; похожие поля секретов исключаются. Ограниченная память известных токенов — не универсальное распознавание любого старого секрета из любого файла.

По умолчанию паника отправляет категорию/время/необходимость ручного управления, без исходной строки чата и без сервера. Opt-in подробности дополнительно очищаются от известных имён игроков, координатных шаблонов, ссылок/email/IPv4/UUID/секретов. Произвольное неизвестное имя, необычная запись координат или иной приватный текст не гарантированно распознаются. Поэтому подробности выключены.

PNG требует **обоих** разрешений: скриншоты Discord + явное согласие на незамаскированный снимок. Только локальный обычный PNG из папки panic-screenshots, ограниченный размер, проверка сигнатуры; кадры ограничены по частоте. **Изображение может показать чат, имена, табло и другие личные данные; очистка текста не редактирует пиксели.** Не включай, если это неприемлемо. Локальный EventLog сохраняет игровые детали, включая возможные координаты/ники; известные ссылки/секреты редактируются, но весь журнал анонимным не является.

## Приёмка пользователем (не выполнялась агентом)

1. Сначала резервная копия config; оставить один Kaelix JAR. Новые опции OFF, начать с короткой безопасной сессии без финансового сервиса.
2. Проверить общий/рабочий бюджет, рабочие периоды, перерыв и отмену вводом; счётчики не должны сбрасываться на штатном сервисе.
3. Отдельно проверить нормальный разрыв и конечный reconnect, несовпадение источника/руки/точки и отказ resume. После паники не должно быть reconnect/resume без нового ручного запуска.
4. История после рестарта — справка, никакого запуска. Не публиковать raw config/log/screenshots.
5. Только по своему желанию включить текстовые события Discord на отдельном webhook, проверить доставку/подавление повторов/отключение. PNG и подробности сначала оставить OFF. Не создавать нагрузку ради получения 429.
6. Перед stable сообщить результаты. Без игрового подтверждения сборка остаётся alpha.

Сборка разработки: только `bash gradlew --no-daemon jar`, исходники/API/архивы. Без Minecraft, серверов, тестов, stress, симуляций, benchmarks, GUI-стендов. Без commit/push/публикации. Aether — read-only reference, код/ассеты не копировались. KeyAuth отложен.
